# vod2pod-rss — Agent Instructions

## Setup & Commands

### Nix (recommended on NixOS)

```bash
nix develop              # enter dev shell (cargo, rust-analyzer, ffmpeg, yt-dlp, redis)
nix build                # build release binary → result/bin/vod2pod
nix flake check          # validate: builds package for x86_64 + aarch64
nixos-rebuild switch --flake .#test  # deploy (requires full system config)
```

Regenerate `Cargo.lock` when dependencies change: `nix develop -c cargo update`.

### Legacy (Makefile)

```bash
make install-ubuntu-deps    # or install-fedora-deps (installs ffmpeg, redis, rust, cargo-watch, yt-dlp)
make start-deps             # starts Redis via docker-compose.dev_environment.yml (REQUIRED before run/test)
make run                    # redis-cli flushdb + cargo run
make hot-reload             # cargo watch with auto-flush on version change
make test                   # cargo test -- --nocapture
```

`.env` is auto-generated by `make install-*`. Edit it for API keys (`YT_API_KEY`, `TWITCH_SECRET`, `TWITCH_CLIENT_ID`). Set `RUST_LOG=DEBUG` for verbose logs.

## Architecture

Single Cargo package (`vod2pod-rss`). Binary at `src/main.rs`, lib at `src/lib.rs`.

Five modules:
- **`configs`** — env-var-backed config (`ConfName` enum). Read via `conf()`.
- **`provider`** — YouTube, Twitch, PeerTube, Generic providers. All implement `MediaProvider` trait (`generate_rss_feed`, `get_stream_url`, `domain_whitelist_regexes`). Dispatched via `Provider::from(url)` which matches URL against provider regex whitelists, falling back to `GenericProvider`.
- **`rss_transcodizer`** — rewrites raw RSS feeds to inject transcoded stream URLs.
- **`transcoder`** — live ffmpeg transcode endpoint (MP3 192k default).
- **`server`** — actix-web routes and `spawn_server()`.

Adding a provider: create `src/provider/<name>.rs` implementing `MediaProvider`, add to `mod.rs`, register in the `generate_static_dispatcher!()` macro call.

## Testing

- Unit tests: `cargo test` (no Redis needed).
- Integration tests in `tests/integration_tests.rs` spin up the server via `spawn_app()` and hit real endpoints. **Require Redis running** (`make start-deps`).
- Tests suffixed `requires_api_key` need `YT_API_KEY` / `TWITCH_SECRET` + `TWITCH_CLIENT_ID` set in `.env`. CI skips them if secrets are absent (`--skip requires_api_key`).
- Tests hit real YouTube/Twitch channels — they can fail if upstream content changes.

## Docker

Multi-stage build targeting `arm/v7`, `arm64`, `amd64`. Builder uses `rust:1.88` on `$BUILDPLATFORM`; runtime is `debian:bookworm-slim`.

```bash
make image              # build locally (uses docker-compose logic to detect docker-compose vs docker compose)
```

Production compose: `docker-compose.yml` (api_keys helper service, vod2pod + redis). Dev compose: `docker-compose.dev_environment.yml`.

## Constraints & Gotchas

- **Redis is mandatory** — app panics on startup if Redis is unreachable. Version-change auto-flushes the DB.
- **`Cargo.lock` is force-added to git** — tracked for Nix flake reproducibility despite `.gitignore`. Regenerate with `nix develop -c cargo update` when dependencies change.
- **`openssl = { vendored }`** in `Cargo.toml` is only for cross-compilation in CI. Don't remove it.
- **Dockerfile strips dev-dependencies** before `cargo fetch` for cache efficiency (`sed '/\[dev-dependencies\]/,/^$/d'`).
- **`.env` is gitignored** — never commit secrets. The `api_keys` Docker service pattern keeps keys out of the main container.
- **Provider regexes must not overlap** — `domain_whitelist_regexes()` drives static dispatch; overlapping patterns cause wrong provider selection.
